## Проверка

Выполнено в изолированном окружении Python 3.11 с `opencv-python-headless` (для Linux CI):

```bash
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
```

Результат: **42 passed, 2 skipped**. Пропущенные тесты требуют установленный Tkinter; в Windows-поставке с Tk они должны выполняться в GUI smoke-прогоне. Новые проверки находятся в `tests/test_core_refactor.py` и покрывают формулы, ROI, ограниченную историю, CSV, Excel, baseline-математику, метки и fragmentированное FFmpeg-чтение.

## Открытые риски и следующий этап

Это не скрытые исправления, а ограничения, которые нельзя честно снять без оборудования/валидационных данных.

1. **Научная валидация порогов.** Алгоритм переходов технически тестируем, но значения порогов нельзя объявлять универсально точными без эталонных лабораторных серий. См. раздел 5 в `ARCHITECTURE_AND_REQUIREMENTS.md`.
2. **Полный экспорт долгих сессий.** Графики ограничены, но `saved_data` сознательно сохраняет полный ряд для финального Excel. Для многочасового high-FPS анализа требуется потоковый writer (SQLite/Parquet/поэтапный Excel), иначе память будет расти пропорционально длине сессии.
3. **Крупные UI-модули.** `live_graph.py`, `settings_window.py`, `setup_app.py` и `runner.py` всё ещё крупные. Безопасная следующая декомпозиция: `graph_layout`, `transition_rules`, `formula_editor`, `roi_player_controller`, `session_controller`. Её следует выполнять небольшими PR с UI regression/smoke-тестами, а не механическим переносом тысяч строк.
4. **Обработка исключений.** В legacy-коде осталось много широких `except Exception` для работы с разнородными драйверами. Следующий этап — заменить их на узкие исключения и структурированный `logging`, показывая оператору контекст ошибки.
5. **Лицензирование.** Локальный HMAC с секретом в клиенте препятствует случайной правке, но не является криптографической защитой от мотивированного обхода. Для коммерческой защиты нужна отдельная модель лицензирования/подписи и политика приватности.
6. **Интеграционные тесты железа.** Нужны Windows hardware-in-the-loop тесты: USB-камера, MiiCam, RTSP обрыв/восстановление, запись/восстановление видео и настоящий PyInstaller/installer smoke-test.
