# Требования и архитектура «ЭЛЮТЕК — RGB SARA-анализ»

**Статус документа:** актуализирован после рефакторинга.

**Назначение:** превратить знания, распределённые между интерфейсом и исходным кодом, в проверяемые требования. Это приложение является инструментом поддержки лабораторной процедуры; автоматическая метка не заменяет решение оператора и не является метрологически аттестованным результатом без валидации методики лабораторией.

## 1. Контекст и границы системы

Приложение принимает поток кадров с камеры или видеофайла, вычисляет усреднённые BGR/RGB значения внутри ROI, получает производные показатели, показывает их в реальном времени и помогает оператору отмечать переходы SARA-фракций. Основная целевая платформа — Windows 10/11 x64.

В систему входят:

- выбор USB/MiiCam/IP/RTSP-источника либо локального видео;
- настройка и отображение ROI;
- потоковый расчёт RGB-метрик и transition score;
- визуализация, уведомления, ручные и автоматические метки;
- запись видео, аварийный CSV, экспорт Excel и графиков;
- локальные настройки и локальная лицензия.

В систему **не** входят: управление лабораторными насосами/клапанами, облачная передача данных, централизованное управление пользователями, метрологическая калибровка оборудования или подтверждение химического состава без методики лаборатории.

## 2. Функциональные требования

| ID | Требование | Приёмочный критерий |
|---|---|---|
| FR-01 | Открывать локальную камеру, MiiCam/ToupCam, IP/HTTP, RTSP и поддерживаемый видеофайл. | Для доступного источника получен хотя бы один непустой BGR-кадр; ошибка источника понятна пользователю. |
| FR-02 | Давать оператору выбрать прямоугольную или круглую ROI, перемещать/масштабировать её и не выходить за кадр. | Координаты ROI всегда находятся в границах кадра, включая кадры меньше минимального размера ROI. |
| FR-03 | В реальном времени вычислять R, G, B, сумму RGB, Log10(B/R), Log10(B/G), треугольные координаты и производные показатели. | Для фиксированного эталонного кадра/последовательности значения совпадают с расчётом в тесте с заданной точностью. |
| FR-04 | Вычислять наклоны и показатели перехода только после накопления необходимого числа точек. | До `min_points` отсутствуют ложные производные/базовые значения; после накопления расчёт воспроизводим. |
| FR-05 | Показывать синхронизированные графики и позволять менять набор графиков, масштаб, временную единицу и тему. | Все видимые графики имеют общий X-диапазон после авто-скролла, zoom и pan. |
| FR-06 | Обнаруживать SAT→AROM, AROM→BR и BR→ABR по настраиваемым порогам, окнам времени и подтверждению. | При подаче валидационного ряда создаётся ровно одна метка при выполнении правила; cooldown предотвращает дубликаты. |
| FR-07 | Позволять задавать безопасные пользовательские численные переменные, графики и правила автометок. | Допустимая формула рассчитывается одинаково в UI и экспорте; запрещённая конструкция отклоняется до исполнения. |
| FR-08 | Поддерживать ручные метки, их цвет/описание, хранение и экспорт. | Метка выводится на графиках и попадает в листы Excel без потери времени и атрибутов. |
| FR-09 | Во время анализа писать аварийный CSV и по завершении формировать Excel с данными, метками и пользовательскими графиками. | CSV открывается даже по относительному пути, периодически сбрасывается на диск; Excel открывается в Excel/LibreOffice и не содержит исполняемых пользовательских формул. |
| FR-10 | Записывать видео и уметь открывать/перематывать локальный файл без создания дублирующихся участков графика. | При перемотке назад временная ось остаётся строго монотонной. |
| FR-11 | Хранить настройки профилей и параметры уведомлений локально. | После перезапуска валидные настройки восстанавливаются; повреждённый файл не мешает запуску. |
| FR-12 | Давать локальный статус лицензии/демо-режима. | Допустимый ключ активирует текущий HWID; неверный ключ не активирует приложение. |

## 3. Нефункциональные требования

| Область | Требование | Как контролировать |
|---|---|---|
| Производительность | Анализ и UI не должны расти по памяти бесконечно во время живой сессии. | `max_points` ограничивает графический буфер кольцевым хранением; профили задают интервалы обработки. Нагрузочный тест следует проводить на целевой камере. |
| Отзывчивость | Захват, запись и предварительный просмотр не должны блокировать основной UI-поток. | `CameraWorker`, `PreviewWorker`, FFmpeg capture и recorder работают в фоновых потоках; ручной smoke-тест UI. |
| Надёжность | Недоступный источник, неполный кадр, сбой CSV и повреждённый файл должны деградировать в понятную ошибку, а не завершать анализ аварийно. | Unit-тесты на частичные pipe-чтения, CSV и ROI; ручной тест обрыва RTSP. |
| Целостность данных | Время точек должно быть монотонным; экспорт не должен допускать Excel formula injection. | Регрессионные тесты перемотки и экспорта; префикс `'` для небезопасных строк. |
| Воспроизводимость | Пороговые алгоритмы требуют фиксированных экспозиции, баланса белого, освещения и ROI. | Лабораторный протокол калибровки + эталонные видео до утверждения порогов. |
| Безопасность | Пользовательские формулы не имеют доступа к файлам, процессам или Python internals. | AST allow-list в `src/utils/formulas.py`; тесты на `__import__`, dunder-атрибуты и неизвестные имена. |
| Совместимость | Основной релиз должен собираться под Windows x64; тесты ядра должны стартовать без Tk display. | PyInstaller build на Windows, CI compile+unittest на Linux; GUI-тесты пропускаются только при отсутствии Tk/display. |
| Сопровождаемость | Новые изменения не должны смешивать вычисления, I/O и отрисовку без теста. | Модули `analysis`, `data`, `utils`, `gui`; обязательный запуск `unittest` в CI. |
| Наблюдаемость | Ошибки видео/FFmpeg/CSV должны быть доступны в журнале или сообщении UI без сокрытия причины. | Проверка сообщений в UI и тесты поведения отказов; в дальнейшем заменить оставшиеся `print` на `logging`. |
| Приватность | Данные анализа и видео остаются на локальном компьютере, пока оператор не экспортирует/не передаст их сам. | Не добавлять сетевую телеметрию без отдельного согласия и политики хранения. |

## 4. Архитектура и ответственность модулей

```text
main.py
  └─ gui/setup_app.py             старт, выбор источника, превью
       ├─ gui/settings_window.py  настройки и конструктор правил
       └─ analysis/runner.py      orchestration одной сессии
            ├─ analysis/camera_worker.py   захват → метрики → bounded graph buffer
            ├─ analysis/ffmpeg_capture.py внешние file/RTSP capture
            ├─ analysis/video_recorder.py  асинхронная запись
            ├─ gui/live_graph.py           отображение и автометки
            └─ data/{csv_logger,excel_exporter}.py

utils/
  ├─ math_utils.py     чистые численные функции
  ├─ formulas.py       единый безопасный язык пользовательских формул
  ├─ helpers.py        источники видео, ROI, поиск камер
  ├─ miicam_wrapper.py ctypes-адаптер драйвера
  └─ license_manager.py локальное лицензирование
```

### Инварианты ядра

1. Все связанные серии имеют одинаковый логический порядок точек.
2. `CameraWorker.snapshot()` возвращает графическую историю в хронологическом порядке, даже после переполнения кольцевого буфера.
3. `saved_data` хранит полный ряд для итогового экспорта текущей сессии; `max_points` ограничивает именно историю для live-графиков. Для очень долгих сессий следующий этап — потоковый Excel/SQLite-экспорт, чтобы ограничить и этот список.
4. ROI, возвращаемая `compute_roi_means`, совпадает по размеру с фактически обработанным срезом кадра.
5. Пользовательская формула проходит один и тот же валидатор в UI, live-графике и Excel-экспорте.

## 5. Лабораторная валидация, необходимая до производственного применения

1. Зафиксировать геометрию оптического тракта, источник света, экспозицию/gain/WB и расположение ROI.
2. Собрать репрезентативные видео для всех типов образцов и нормальных/аномальных сценариев.
3. Разметить истинные моменты переходов независимым лабораторным методом.
4. Рассчитать precision/recall, задержку и ложные срабатывания для каждой границы фракций.
5. Утвердить значения порогов/подтверждений отдельно для конкретного детектора и методики; версионировать профиль вместе с отчётом.
6. Повторить тест после обновления драйвера камеры, алгоритма, освещения или версии приложения.
